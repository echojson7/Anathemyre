# Материалы

Шов «материал ↔ свет» (`docs/invariants.md`, шов 6): материал отдаёт `Surface`, свет её освещает.

- **Вид материала** — файл `data/shaders/materials/<вид>.glsl` с функцией `Surface surf_<вид>(SurfIn i)`.
  Узор считается в мировых координатах (без UV), квадратами TEXEL и шумом по целым номерам квадратов.
  Сейчас виды: `flat` (ровный цвет), `ground` (голая земля), `concrete` (бетон руины: щиты опалубки, анкерные отверстия, поры, пятна; потёки — декали, `docs/ostov.md`),
  `metal` (металл с пятнами ржавчины), слои земли: `sand` (песок с рябью и полосами вдоль ветра), `sand_dune` (тот же песок с ветром пустыни: рябь двух масштабов, языки осыпей на подветренных склонах; общий код — `sand_surf()` в `sand.glsl`), `gravel` (щебень россыпью эллипсов),
  `rock` (камень: слои, грани, трещины; им же покрыты камни рассыпки), `grass` (травяной покров: пятна сухой
  травы, кочки двух размеров с тенью у основания, штрихи полёгшей травы), `water` (гладь протоков: рябь
  нормалью, полосы ветра). Сухая земля — вид `ground` с трещинами такыра.
- Плавные пятна — `fbm_n()` (градиентный шум по плоскости, октавы степенями двойки) в `surface.glsl`, а не
  `value_noise()`: у шума значений пятна квадратные, это и давало «процедурный камуфляж» этапа 2.
  Узор, который строится в повёрнутых координатах (штрихи травы, полосы ветра у песка), берёт мировые метры
  `cam_chunk · 256 + p`, иначе прыгал бы при смене чанка камеры.
- `Surface.metal` — где виден металл материала (ржавчина, краска — 0), `surface()` умножает на `metal` таблицы.
  `Surface.nvar` — дисперсия наклона узора, погашенного мельче пикселя: `surface()` переводит её в шероховатость
  (Токсвиг, против искр без TAA, `docs/light.md`). Новый вид, который гасит наклон нормали по `kf`, отдаёт её.
- `Surface.height` — высота узора 0..1: на стыке слоёв земли побеждает выступающий (`docs/terrain.md`).
  `SurfIn.foot` — след пикселя в метрах, непрерывный: узор мельче пикселя гаснет по нему, а не по ступеням ячейки.
- **Номер вида** — место файла в списке по имени. `tools/matgen.sh` (зовёт Makefile) из этого списка пишет и
  `switch` в шейдере (`build/<цель>/shaders/gen/materials.glsl`), и список для игры
  (`build/<цель>/data/material_kinds.txt`), поэтому они не расходятся. Новый вид — новый файл, больше ничего.
- **Таблица материалов** — `data/materials.txt` (свой текстовый формат, `docs/text.md`):

      material <имя> <вид>
          color r g b      линейный цвет
          rough k
          color2 r g b     второй цвет (смысл — у вида)
          texel м          квадрат узора; должен делить 256 м нацело (0.1, 0.0625, 0.5…)
          extra a b c d    параметры вида (описаны в шапке его .glsl)
          metal k          0 — диэлектрик (по умолчанию), 1 — металл: color — цвет отражения F0 (docs/light.md)

  Номер 0 — «missing», его ставит игра. Материал в сетках и сцене — по имени.
- **Смесь двух материалов** вершины — не плавная: ячейка берёт материал 1 с вероятностью доли смеси (по хешу
  ячейки). Так переход тоже остаётся «пиксельным».
- `SurfIn.p` — точка мира в метрах от начала чанка камеры, номера квадратов узора — `world_cell()`: чанк камеры ×
  квадратов на чанк + место. Узор не плывёт при движении камеры и не рвётся на границе чанков.
- Узор и свет считаются на GPU и в шаг мира не входят: запреты по float на них не распространяются.
- **Бетон Остова** (`docs/ostov.md`) — четыре материала одного вида: `concrete` (стены, опалубка 1 × 0.5 м и анкеры), `concrete_soffit`
  (низ плит, темнее и бурее, без опалубки), `concrete_floor` (верх плит и ступеней, вытерт), `concrete_break` (свежий
  излом светлее, крупное зерно). Цвета подобраны по фото концепта на глаз.
- **Материалы декалей** (`decal_water`, `decal_grime`, `decal_dust`, `decal_stain`, `decal_damp`, `decal_salt`) — вид
  `flat`; декаль берёт из них цвет, шероховатость и силу (`extra a`), узор задаёт вид декали (`docs/ostov.md`).
