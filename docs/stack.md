# Стек

Перенесено из старого проекта (там проверено и работало), кроме пунктов «новое в v2».

## Язык и сборка
- Чистый C11, gcc или clang, сборка одним `Makefile` (без CMake). C++ отклонён.
- Флаги: всегда `-Wall -Wextra -Wpedantic -Wshadow` без предупреждений (в CI `-Werror`).
  Релиз `-O2`, отладка `-O0 -g3 -fsanitize=address,undefined` (на Linux).
- Цели сборки: **Windows `.exe`** (основная, играет пользователь) — кросс-компиляция MinGW-w64 из WSL/Linux или
  MSYS2 на Windows; **Linux** (X11) — для CI, запуска без окна и санитайзеров.
- `tools/run.sh` (появится на этапе 0): `git pull`, сборка, запуск. Пользователь запускает только его.

## Рантайм игры
- Без игровых движков (Unity, Unreal, Godot, raylib и т.п.). Ядро, симуляция, рендер, ИИ, анимация — свои.
- Разрешено: libc, POSIX/pthreads, системные API (Win32, X11), Vulkan через драйвер, звук (winmm/WASAPI, ALSA).
- Сторонняя библиотека в рантайме — только если выполнены все 5 условий сразу (правило пользователя 2026-10-30):
  1) решает задачу заметно лучше нас и задача уже на очереди; 2) лицензия MIT/zlib/BSD/Apache-2.0/CC0, без GPL/LGPL;
  3) C или C-интерфейс, исходники в `third_party/` с версией, собираются нашим Makefile;
  4) не участвует в шаге мира (детерминизм от неё не зависит); 5) спрятана за нашим тонким слоем.
  Каждую согласует пользователь, запись — в `docs/decisions.md`.
- Отладочная сборка может иметь профилировщик (например Tracy), в релизе ни строки.

## Графика
- **Только Vulkan** (1.3, dynamic rendering). OpenGL не делаем (решение пользователя 2026-10-31).
- Функции Vulkan грузим сами; заголовок `vk.h` генерируем из `vk.xml` нужной версии (как `tools/vkgen` в складе).
- Шейдеры GLSL → SPIR-V офлайн (`glslangValidator`), проверка `spirv-val`. Игра читает готовый `.spv`.
- Скиннинг на GPU, до 4 костей на вершину.

## Ассеты
- Игра читает только свои бинарные форматы (`.mesh`, `.skel`, `.anim`, `.tex`, `.font`), рассчитанные на быструю
  загрузку в арену при старте. Никаких парсеров FBX/glTF/BVH в игре.
- Конвертеры живут в `tools/` и могут использовать любые свободные библиотеки и Python.
- **Люди:** MakeHuman (CC0), конвертер из склада (`tools/humanconv`, 5 LOD, морфы). **Новое в v2:** скелет
  MakeHuman `game_engine` (около 50 костей, позвоночник из нескольких звеньев, шея, ключицы) вместо урезанных
  20 костей, чтобы на него ложился захват движения. Окончательный выбор скелета — по итогу этапа 2.
- **Анимации (новое в v2): захват движения, а не позы формулами.**
  - CMU Motion Capture Database (BVH, бесплатно, можно в коммерческой игре, нельзя перепродавать сами данные) —
    ходьба, бег, базовые движения.
  - Mixamo (бесплатно для игр, нужен аккаунт Adobe, скачивает пользователь) — удары, блоки, уклоны, реакции.
    Сами файлы Mixamo не распространяем отдельно, в игре они только внутри наших `.anim`.
  - Платные паки захвата для боя мечом — если бесплатного не хватит, решает пользователь.
  - Перенос на наш скелет (ретаргет) — офлайн: Blender из командной строки (FBX/BVH → наш промежуточный формат),
    затем свой конвертер в `.anim` с метками (окна удара, шаги, точки контакта).
- Шрифт интерфейса: IBM Plex Sans (SIL OFL), конвертер `tools/fontconv` из склада.

## Симуляция
- Фиксированный шаг (предложение: 60 Гц), детерминированный RNG с зерном, повтор боя бит в бит из зерна.
- Data-oriented: структуры массивов, пулы и арены при старте, без malloc/free в цикле.
- Пространственная сетка вместо проверок «все со всеми». Job system на pthreads, когда будет что распараллелить.

## Инструменты разработки
- git + GitHub (`echojson7/Anathemyre`), ветка v2 — `claude/project-thread-vwjaxp`.
- CI: GitHub Actions (сборка Linux и Windows без предупреждений, отладка с санитайзерами, проверка повтора).
- Python 3 + numpy для конвертеров, Blender 4.x для ретаргета, Xvfb + lavapipe для кадров без окна.
- Профилирование: встроенный замер кадра и шага, `perf` на Linux.
