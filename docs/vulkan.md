# Vulkan-бэкенд

Состояние на 2026-10-30, этап 3 плана перехода (Vulkan вторым бэкендом, GL остаётся запасным и эталоном кадров).
Код: `src/render/rb_vk.c`, `src/render/rb_vk.h`, `src/render/vk.h`; выбор бэкенда — `src/render/rb.c`;
платформа — `platform_use_vulkan`, `platform_native`, `platform_vk_loader`. API слоя — `src/render/rb.h`, общий с GL.

## Как включить

НАСТРОЙКИ → ОТЛАДКА → «РЕНДЕР: VULKAN (ПОСЛЕ ПЕРЕЗАПУСКА)». Выбор пишется в `anathemyre.cfg` рядом с папкой `data`
(строка `render vulkan` или `render gl`, файл в .gitignore) и действует со следующего запуска: окно и все ресурсы
создаются под бэкенд заново. Строка «РЕНДЕР СЕЙЧАС» показывает, чем рисуется кадр. Ключи `--vk` и `--gl` перекрывают файл.
Если Vulkan не поднялся (нет драйвера, нет нужных расширений, нет `.spv`), в журнале СБОЙ с причиной, и игра сама
запускается на GL. По умолчанию пока GL: Vulkan станет основным после проверки на RTX (решение пользователя 2026-10-30).

## Что умеет

| Часть | Как сделано |
|---|---|
| Загрузка | `libvulkan.so.1` (dlopen) / `vulkan-1.dll` (LoadLibrary); всё остальное через `vkGetInstanceProcAddr` и `vkGetDeviceProcAddr`. Exe по-прежнему зависит только от системных DLL |
| Заголовок | `vk.h` генерирует `tools/vkgen` из реестра Khronos `vk.xml` (версия и sha256 в `gen.sh`). Только функции из `want.txt` и типы, от которых они зависят |
| Устройство | Обязательно: Vulkan 1.3 (dynamic rendering, synchronization2), push descriptors, depth clip control, multiDrawIndirect, drawIndirectFirstInstance, depthClamp, shaderDrawParameters. Если есть: robustness2 (пустые привязки). Выбор: дискретная > встроенная > виртуальная > процессор |
| Validation | В отладочной сборке всегда (если слой установлен), в релизе — `ANA_VK_VALIDATION=1`; `ANA_VK_VALIDATION=0` выключает. Ошибки идут в журнал как СБОЙ, их число — при выходе |
| Показ | FIFO при VSYNC, без него IMMEDIATE (нет — MAILBOX, нет и его — FIFO). Swapchain пересобирается при смене размера, свёрнутое окно не показывается, но кадр считается |
| Кадры в полёте | `RB_FRAMES` = 3: у слота свой буфер команд, забор, семафор получения, кольцо загрузок 16 МБ, корзина и кусок пула меток времени |
| Память | Свои блоки по 64 МБ (картинки и буферы в разных), свободные куски списком с первым подходящим и склейкой соседей. От 32 МБ — своё выделение. Буфер `RB_BUF_DYNAMIC` видим с CPU (сначала в памяти видеокарты, если есть) и пишется прямо `memcpy` |
| Загрузки | `rb_buf_write` и `rb_tex_write` копируют через кольцо слота командами в буфере кадра — встают перед следующими вызовами, как в GL. Кольцо кончилось — записанное отправляется и ждётся. Буфер команд начинается сам при первой команде, даже до первого кадра |
| Текстуры | Все форматы `RbFmt`; D24 — `X8_D24`, если его можно рисовать и читать с фильтром, иначе D32F. Созданная картинка очищается (нули, глубина 1), как дают драйверы GL. Виды мипов и слоёв для целей и записи — кешем у текстуры |
| Конвейеры | Модули из `data/spv` по рецепту (ниже). Привязки читаются из SPIR-V: набор с этими типами общий у всех конвейеров с ним. Под каждый набор форматов целей прохода — свой вариант конвейера (первый собирается сразу по `RbPipeDesc`, остальные — при первом вызове) |
| Привязки | Push-дескрипторы: перед вызовом уходят только сменившиеся, при смене набора — все. Шейдер читает пустую привязку — пустой дескриптор (нули), как блок GL без текстуры; без robustness2 вызов пропускается с СБОЕМ |
| Вершины | Шаг потока задаётся при привязке: поток нулей (сетка без весов) — с шагом 0. Вход шейдера без атрибута в раскладке читает (0, 0, 0, 1), как в GL |
| Барьеры | Все картинки всегда в раскладке GENERAL. Перед проходом, копией, вычислением и показом — полный барьер памяти, если перед ним была работа GPU. Копия или вычисление посреди прохода приостанавливают его и продолжают с загрузкой целей |
| Метки времени | Пул на `RB_FRAMES` × наборы × метки; результаты слота забираются без ожидания, когда слот снова свободен. ЗАМЕР ПО ЭТАПАМ и столбцы GPU работают как в GL |
| Удаление | Конвейеры, буферы, картинки, виды и память удаляются, когда их слот снова свободен |

## Кадр как в GL

Окно — своя картинка RGBA8 + глубина D32F. Строка 0 в памяти — низ картинки, как у GL. Поэтому `rb_viewport`,
`rb_scissor`, `rb_clear_rect`, `gl_FragCoord` и uv текстур берут те же числа, что в GL, без пересчёта. Переворот один:
в конце кадра картинка копируется в swapchain blit'ом снизу вверх. `rb_read_window` отдаёт кадр снизу вверх, как `glReadPixels`.

Отличия, которые закрывает слой, а не шейдеры:
- Глубина: GL отсекает по z в [-1, 1], Vulkan по [0, 1]. `VK_EXT_depth_clip_control` с `negativeOneToOne` — шейдеры те же.
- Обход граней: строки те же, но знак площади в Vulkan обратный, поэтому лицевой у GL CCW здесь — `VK_FRONT_FACE_CLOCKWISE`.
- Номер экземпляра: `gl_InstanceIndex` считает и первый экземпляр вызова, `gl_InstanceID` GL — нет;
  `RB_INSTANCE_ID` в `rb.glsl` вычитает `gl_BaseInstanceARB`.
- Цвет: кадр уже в гамме экрана (окно GL без sRGB), поэтому swapchain UNORM.
- Выборка: семплеры как GL_NEAREST / GL_LINEAR без мипов — всегда нулевой мип вида (maxLod 0).

## Шейдеры

Шейдеры общие с GL (`data/shaders`), для Vulkan собраны офлайн в SPIR-V (`glslangValidator`, цель vulkan1.3).
Рецепт стадии — строка `tools/spv/list.txt`: `стадия [-DИМЯ[=ЗНАЧ] ...] файлы`. Исходник — `#version 450 core`,
`rb.glsl`, файлы по порядку; строки `#define` из `RbPipeDesc.defines` становятся ключами `-D`; `VULKAN` ставит glslang.
Имя `.spv` — файлы через «+», определения через «~», стадия: `frame.glsl+skin.glsl+scene.vert~SHADOW_PASS.vert.spv`.
Игра считает рецепт так же (`rb_spv_recipe` в `rb.c`) и берёт `data/spv/<имя>.spv`.

Готовые `.spv` и `data/spv/index.txt` (sha256 исходника) лежат в репо: для игры и `run.sh` ничего не меняется.
CI пересобирает во временную папку, сверяет хеши и прогоняет `spirv-val`.
- Правка шейдера: `./tools/spv/build.sh`.
- Новый конвейер: `ANA_SPV_LIST=tools/spv/list.txt ./build/anathemyre --frames 3 --shot build/x.ppm` (под GL
  игра дописывает в список рецепты всех своих конвейеров), затем `./tools/spv/build.sh`. Забытый `.spv` — СБОЙ
  с готовой строкой для списка, и игра уходит на GL.
- Входы и выходы между стадиями — с явным `layout(location = N)`: glslang без них SPIR-V не соберёт (`mat3` занимает 3 места).

## Проверка

`make vkcheck` собирает `build/vkcheck` (на Linux с ASan/UBSan): через слой rb рисует очистку, конвейер
`vkcheck.vert/frag` (градиент по `gl_FragCoord.y`, бледно-зелёная полоса у нижнего края) и красный квадрат
`rb_clear_rect`, читает кадр и сверяет пиксели; код выхода 1 при сбое или ошибке validation.
В CI ещё кадр самой игры на Vulkan (lavapipe, ASan, validation): любой СБОЙ — провал.

Проверено 2026-10-30 на lavapipe (Mesa 25.2) против GL на llvmpipe, 24 кадра (этапы сцены 0–11, близко и далеко,
ночь, долина, люди, стенд, осмотр, без пиксельности, без VRS, без MultiDraw, AO в половине, шум хешем):
картинка та же, 99.5 % пикселей и больше совпадают до 2/255, средняя разница 0.01–0.1 из 255. Расходятся отдельные
пиксели на рёбрах и на решениях по глубине (выбор ближайшей из четырёх точек в пиксельности, края теней).
Ошибок validation (включая проверку синхронизации) и ASan нет.

## Чего пока нет (этапы 4–5)

- Шейдинг блоками (`VK_KHR_fragment_shading_rate`): пункт ШЕЙДИНГ БЛОКАМИ под Vulkan пока ничего не делает, каждый
  пиксель считается отдельно. Поэтому на RTX Vulkan сейчас может быть медленнее GL в полной сцене.
- Барьеры точечные и раскладки под проход: сейчас полный барьер между проходами — просто и надёжно, но лишние ожидания GPU.
- Выбор показа (FIFO / MAILBOX / IMMEDIATE) в меню.
