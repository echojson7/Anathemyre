# Vulkan-бэкенд

Состояние на 2026-10-30, этап 2 плана перехода (Vulkan вторым бэкендом, GL остаётся). Код: `src/render/rb_vk.c`,
`src/render/rb_vk.h`, `src/render/vk.h`, платформа — `platform_use_vulkan`, `platform_native`, `platform_vk_loader`.
API слоя — `src/render/rb.h` (общий с GL). В игру Vulkan войдёт пунктом РЕНДЕР: GL / VULKAN; пока его гоняет
отдельная программа `vkcheck`.

## Что умеет сейчас

| Часть | Как сделано |
|---|---|
| Загрузка | `libvulkan.so.1` (dlopen) / `vulkan-1.dll` (LoadLibrary); всё остальное через `vkGetInstanceProcAddr` и `vkGetDeviceProcAddr`. Exe по-прежнему зависит только от системных DLL |
| Заголовок | `vk.h` генерирует `tools/vkgen` из реестра Khronos `vk.xml` (версия и sha256 в `gen.sh`). Только функции из `want.txt` и типы, от которых они зависят. X11 и windows.h не нужны |
| Устройство | Vulkan 1.3: dynamic rendering, synchronization2, push descriptors, multiDrawIndirect — обязательны. Если есть: depth clip control, depth clamp, gl_DrawID (shaderDrawParameters), indirect count. Выбор: дискретная > встроенная > виртуальная > процессор |
| Validation | В отладочной сборке всегда (если слой установлен), в релизе — `ANA_VK_VALIDATION=1`; `ANA_VK_VALIDATION=0` выключает. Ошибки идут в журнал как СБОЙ и считаются |
| Окно | X11 (Xlib) и Win32. Окно без GL-контекста |
| Показ | FIFO / MAILBOX / IMMEDIATE (`rb_vk_set_present`), чего нет у драйвера — FIFO. Swapchain пересобирается при смене размера, свёрнутое окно (0×0) не показывается, но кадр считается |
| Кадры в полёте | `RB_FRAMES` = 3: у каждого слота свой буфер команд, забор и семафор получения; готовность к показу — семафор на каждую картинку swapchain |
| Удаление | Освобождённый конвейер удаляется, когда его слот снова свободен (GPU мог ещё рисовать им) |

## Кадр как в GL

Окно — своя картинка RGBA8 + глубина D32F. Строка 0 в памяти — низ картинки, как у GL. Поэтому `rb_viewport`,
`rb_scissor`, `rb_clear_rect` и `gl_FragCoord` берут те же числа, что в GL, без пересчёта. Переворот один: в конце
кадра картинка копируется в swapchain blit'ом снизу вверх (стоит доли миллисекунды). `rb_read_window` отдаёт кадр
снизу вверх, как `glReadPixels`.

Отличия, которые закрывает слой, а не шейдеры:
- Глубина: GL отсекает по z в [-1, 1], Vulkan по [0, 1]. С `VK_EXT_depth_clip_control` (NVIDIA, AMD, Intel, lavapipe)
  конвейер включает `negativeOneToOne` — шейдеры те же. Без расширения — пересчёт z в вершинном шейдере (этап 3).
- Обход граней: строки те же, но знак площади в Vulkan обратный, поэтому лицевой у GL CCW здесь — `VK_FRONT_FACE_CLOCKWISE`.
- Цвет: кадр уже в гамме экрана (окно GL без sRGB), поэтому swapchain UNORM (`B8G8R8A8` или `R8G8B8A8`).

## Шейдеры

SPIR-V собирается офлайн (`glslangValidator`, цель vulkan1.3) по списку `tools/spv/list.txt`:
`имя стадия [-DИМЯ=ЗНАЧ] файлы...` — файлы склеиваются по порядку. Готовые `.spv` и `data/spv/index.txt`
(sha256 исходника каждого) лежат в репо: для игры и `run.sh` ничего не меняется. CI пересобирает во временную
папку, сверяет хеши и прогоняет `spirv-val`. После правки шейдера: `./tools/spv/build.sh`.
Как рецепт `rb_pipe_make` (rb.glsl + файлы + define) станет строкой списка — этап 3, вместе с переводом шейдеров на слой.

## Проверка

`make vkcheck` собирает `build/vkcheck` (на Linux с ASan/UBSan). `vkcheck --verify` рисует очистку, конвейер
из `.spv` (градиент по `gl_FragCoord.y` и бледно-зелёная полоса у нижнего края) и красный квадрат `rb_clear_rect`
у левого нижнего угла, читает кадр и сверяет пиксели; код выхода 1 при сбое или ошибке validation.
В CI — на lavapipe под Xvfb (`VK_ICD_FILENAMES=.../lvp_icd.json`).

Проверено 2026-10-30 на lavapipe (Mesa 25.2): 0 ошибок validation, квадрат 153,26,20 и полоса внизу и в readback,
и на экране X (снимок окна после swapchain), смена размера 640×360 → 900×300 → 300×500 → 1×1 без ошибок.
