# Журнал решений

Одна строка на решение: дата, что решили, почему. Новые — внизу. Отменённое не стирать, а помечать «отменено ДАТА».

## Перенесено из старого проекта (решения пользователя)
- 2026-10-28 — Чистый C11, Makefile, без движков. Почему: свой код и полный контроль над производительностью. Отменено 2026-11-05 (C++20).
- 2026-10-29 — Пиксельность привязана к миру, одно правило на кадр; пост-обработка без грейда (виньетка, зерно, сканлайны, аберрация).
- 2026-10-30 — Сторонние библиотеки в рантайме только по правилу пяти условий (`docs/stack.md`).
- 2026-10-31 — Только Vulkan, OpenGL удалить. Почему: один путь рендера, меньше проверок.
- 2026-10-31 — Рядом с игроком каждый человек считается полностью, вдали отряд числом; среднего уровня нет. Изменено 2026-11-05: детализация по месту в бою (`docs/invariants.md`).
- 2026-10-31 — В бою максимум 256–512 человек, не 1000.
- 2026-10-31 — Трение и отскок одни на весь мир. Износа вещей нет.
- 2026-10-31 — Отрубленные части тела валяются отдельно и подбираются как вещь (как в Kenshi).
- 2026-10-31 — Тестовые сцены, стенды и замеры — в отладочный модуль, игра собирается без него.
- 2026-10-31 — Свет и его шейдеры делает пользователь: нейросеть не трогает и не подстраивается.
- 2026-10-29 — Имена персонажей старославянские, древнегреческие или старолатинские.
- 2026-10-29 — Пользователь запускает только `git pull && ./tools/run.sh`, других команд ему не давать.

## v2
- 2026-11-02 — Чистый старт отдельной веткой: вертикальный срез (плоскость, два бойца, одно оружие) и рост по этапам. Почему: старый проект строил фундамент и реализм раньше играбельного куска, и качество не дотянуло.
- 2026-11-02 — Анимации из захвата движения (CMU, Mixamo), не позы формулами. Почему: позы из кода выходили любительскими при любом объёме работы.
- 2026-11-02 — Заранее решаются только швы (`docs/invariants.md`), внутренности растут по ходу; после каждого этапа уборка.
- 2026-11-02 — Группа (2 на 2 и больше) ставится сразу после 1 на 1. Почему: групповые проблемы меняют архитектуру, и чем раньше, тем дешевле.
- 2026-11-04 — Модели людей MakeHuman с LOD оставляем (пользователю нравятся), скелет меняется под захват движения.
- 2026-11-05 — C++20 в сдержанном стиле (без исключений, RTTI, STL в шаге мира), clang везде, llvm-mingw для Windows. Почему: операторы для математики, шаблоны для пулов, C++-библиотеки (Jolt, ImGui, VMA) без обёрток; один компилятор — одна арифметика на обеих целях.
- 2026-11-05 — Vulkan 1.3 + VMA + vk-bootstrap; GPU-driven, visibility buffer со светом на ячейку пиксельного правила, кластеры света + froxels, атлас теней с кешем. Почему: сотни огней и плотный туман при бюджете CPU 1 мс; DX12 не проверить на lavapipe.
- 2026-11-05 — В шаге мира свои контейнеры над аренами, `std::pmr` только вне шага мира (`std::pmr` отменено 2026-11-05, см. ниже). Почему: libstdc++ и libc++ по-разному обходят `unordered_map` и упорядочивают равные элементы в `std::sort`.
- 2026-11-05 — Запреты по float в шаге мира (`docs/invariants.md`), одна цель x86-64-v3, шаг 60 Гц. Почему: повтор бит в бит между Windows, Linux, Intel и AMD.
- 2026-11-05 — SDL3 (окно, ввод, вывод звука), свой микшер, звуки в QOA; GLSL; Makefile с unity build; своя XPBD, Jolt — прототип для сравнения (прототип отменён 2026-11-05, см. ниже). Почему: меньше зависимостей, свет пользователь пишет на знакомом языке.
- 2026-11-05 — Правило пяти условий для библиотек: третье условие «C или C++» вместо «только C». Почему: язык игры теперь C++.
- 2026-11-05 — Решения старого проекта — справка, не правила. Сняты цели «3500–4000 к/с в тестовой сцене» и «минимум GTX 970». Почему: v2 начинается с чистого листа.
- 2026-11-05 — Vulkan-Headers + volk вместо своего генератора `vk.h`. Почему: с vk-bootstrap и VMA второй способ грузить Vulkan лишний.
- 2026-11-05 — `std::pmr` не используем нигде; в `tools/` обычный STL. Почему: свои арены нужны всё равно, второй словарь памяти лишний.
- 2026-11-05 — На этапах 0–7 швы кадра и простой forward; visibility buffer, кластеры, froxels, GPU-отсечение и подгрузка чанков — этап 8 «Кадр мира». Почему: срез рисует десятки объектов; при готовых швах смена forward на visibility buffer — замена двух проходов; бета пострадала от фундамента раньше игры.
- 2026-11-05 — Motion matching не планируем, Jolt — только запасной вариант. Почему: для motion matching мало однотипного захвата; своя XPBD в бете работала.
- 2026-11-05 — Минимум: GTX 1060 6 ГБ / RX 580, процессор с AVX2, 8 ГБ ОЗУ; CPU кадра ≤ 1 мс, шаг ≤ 2 мс на 512. GPU меряется таймерами в отладочном меню у пользователя, в CI — только CPU, повтор и картинка. Почему: lavapipe скорость GPU не показывает.
- 2026-11-05 — Игрок командует отрядом приказами (как в Kenshi), бойцы ведут схватку сами; от Dragon's Dogma 2 берём вес удара и читаемость, не управление. Почему: бой 256–512 человек и мир Kenshi. Решила нейросеть по поручению пользователя, можно отменить.
- 2026-11-05 — Попадание: достал ли удар и по какой части — капсулы на костях в активном окне; исход (блок, уклон, урон, броня) — навыки и RNG мира. Почему: бой читается на экране и повторяется бит в бит. Решила нейросеть по поручению пользователя, можно отменить.
- 2026-11-05 — Детализация бойца по месту в бою (схватка / вторая линия / вне боя), не по камере. Почему: полная анимация и физика на всех 512 не влезут в бюджет, а камера не должна влиять на повтор.
- 2026-11-05 — IK стоп в v2 есть (в старом проекте отвергали). Почему: без него ноги из захвата скользят при смешивании и на неровной земле.
- 2026-11-05 — Порядок работы: план этапа коротко, решения об игре — за пользователем, остальное нейросеть делает сама; влитие в v2 по «да»; повтор, сборки и бенч — CI, кадры и видео нейросеть снимает сама в контейнере.
