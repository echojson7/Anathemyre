# Оружие

12 видов оружия первой Anathemyre (беты) вместо меча-заглушки этапа 10. Пока только вид: модели, описания хвата
и ношения, выбор оружия человеку. Бой (досягаемость, отрезок клинка, урон) оружия ещё не знает — удары идут по
дорожкам клипов CMU с двуручным мечом (`docs/people.md`).

    make meshes        → data/meshes/weapon_<имя>.mesh и data/weapons.txt (python3 tools/weapons/build.py data <meshpack>)
    python3 tools/weapons/sheet.py out.png [имена]      лист без игры: вид на плоскость и в три четверти

## Виды
Оружие мира — не кованые мечи, а то, что выжившие сделали из останков машин (облик — `docs/vision.md`). Формы и
длины — со склада беты (`tools/weaponconv` ветки `stage0/test-room`, её `docs/weapons.md`), там они сведены с
концептами и снимками пользователя. Семейство — навык беты; v2 его пока не читает.

## Модели (`tools/weapons`)
Чистый Python без Blender, поэтому идёт в `make meshes`, и CI сверяет байты (`data/meshes`, `data/weapons.txt`).
Каждая деталь — **замкнутое тело** (`kit.Body` фабрики деталей, `docs/parts.md`), детали одной вещи входят друг в
друга (рукоять в гарду), булевых операций нет: `build.py` считает незакрытые рёбра и не пишет сетку, если они
есть (у всех 12 — ноль). Два запуска дают одинаковые sha256.

| Файл | Что |
|---|---|
| `wkit.py` | `Weapon`: лофт по сечениям (`loft`, `rings`), обмотка внахлёст (`wrap`), тело вращения по профилю со ступенями (`profile`), брусок, тор, цилиндр и купол поперёк вещи (отверстия, заклёпки, гайки); перевод осей, нормали по группам, вывод через `meshpack` |
| `onehand.py`, `twohand.py`, `poles.py`, `uniques.py` | вещи по семействам; каждая функция отдаёт вещь и кулак верхней руки |
| `build.py` | таблица хвата и ношения → сетки и `data/weapons.txt` |
| `sheet.py` | лист на numpy (z-буфер) — проверка формы до игры |

- **Оси.** Скрипт строит, как скрипты беты: вдоль вещи +X, толщина Y, лезвие вниз (−Z). Сетка игры: начало —
  середина кулака **верхней** руки (у гарды; у древка — выше по древку), остриё по +Y, лезвие по +X, толщина по Z
  (`wkit.to_game`, поворот без зеркала).
- **Сечение клинка, а не пластилин.** Клинок — лофт по станциям с настоящим сечением: плоскость, спуск, узкая
  подводка (материал `wpn_edge`), ребро ромба, дол у БАЛКИ. Нормали делятся только внутри **группы**: у клинка
  группа — полоса вдоль длины (ребро и подводка резкие поперёк, вдоль клинок гладкий), у обмотки — пояс поперёк
  (виток читается), у рукоятей и колец — вся деталь (круглая). Общее правило «гладко до 60°» сгладило бы ребро
  тонкого клинка в ноль.
- **Материалы — `flat`** (`data/materials.txt`, раздел «Оружие», `wpn_*`). Узоры видов `metal` и сканы CC0
  проецируются по миру (UV нет, `docs/materials.md`): на вещи, которая ходит с рукой, ржавчина и зерно поплыли бы
  по клинку. Поэтому различие — по деталям: плоскость стали, светлая подводка, тёмная кованая сталь, чернёное
  железо, кожа, дерево, тряпьё, шнур, изолента, текстолит, проволока, ржавая приварка, отверстия; у ЛОПАСТИ
  знаки светятся (`glow`). Смесь двух материалов в вершине тоже по миру (`shade.glsl`) — у оружия не используется.
- **Бюджет:** 1.5–7 тыс. треугольников на LOD 0 (ЛОПАСТЬ 12.2 тыс.: 27 колец шнура), предел линта 14 тыс.
  (`tools/assetlint/rules.txt`). Круглые сечения протяжки (`shade` smooth и bands) — по допуску хорды 0.5 мм
  (`wkit.ring`: число точек одно на всю протяжку), гранёные (strips, flat) и гайки — ровно как заданы; брусок
  `slab` с фаской — скругление четвертью круга из 4 отрезков. LOD и кластеры строит
  `meshpack`. Коллайдера нет.

## Описание (`data/weapons.txt`)
Пишет `build.py` из своей таблицы (хват и ношение) и границ сеток (`tip`, `butt`); править таблицу, не файл.
Формат — `docs/text.md`, разбор — `src/view/weapon.cpp` (`weapon_parse`), только кадр: в хеш описаний и шаг мира
не входит.

    weapon <имя>          сетка weapon_<имя>
      family <слово>      семейство (справка)
      hands 1|2|pole      одна рука, две на рукояти, древко
      grip2 <y>           вторая кисть по оси, м (0 — одна рука; двуручное −0.14…−0.2, древко −0.62)
      carry <место> <y>   hip_l — пояс слева (одноручное, точка — у гарды),
                          back — за спиной (двуручное), back_pole — древко за спиной (точка — середина)
      tip <y>  butt <y>   остриё и торец рукояти
      issue <вес>         вес в выборе по зерну (уникальное 0.3, остальное 1)

Договор с видом рук (тред «Исправить позы и оружие в руках людей», 2026-11-15): вид рук берёт из описания
`WeaponHold` (руки, место ношения, `grip2`, `carry_at`, `tip`, `butt`), сам ставит кисти, место на теле и
переходы «убрано / достаёт / в руке / убирает». Ножен нет: оружие висит на ремне голым.

## Выбор оружия человеку
`weapon_pick` (`src/view/weapon.cpp`): доля из хеша зерна внешности (`person_seed`, свой поток бит, не тот, что у
морфов тела) по весам `issue`; вид без сетки пропускается. Только вид: повтор и хеш шага не меняются. Когда бою
понадобится оружие (досягаемость, отрезок клинка по длине, свои клипы на семейство), выбор переедет в шаг мира
столбцом с именем вещи (содержимое по имени, `docs/invariants.md`).

## Чего нет
- Хвата по виду (кисти, древко двумя руками, место на теле) — у вида рук; до него все держат оружие хватом
  прежнего меча: в ударе двумя руками от верхней кисти, вне удара — в правой клинком вперёд-вниз.
- Боя по оружию: досягаемость и отрезок клинка — из дорожек клипа меча (0.10–1.00 м), а не из длины вещи.
- Вида по качеству (ржавчина, щербины), как в бете: нужна поверхность, привязанная к вещи (UV или узор в осях
  сетки), а не к миру.
