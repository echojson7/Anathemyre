# Anathemyre: чистая архитектура игры

Oct 31, 2026 · @lakinsbeast

Разбор ветки stage0/test-room (21aa836, после PR #103 и #104). Главное: один реестр людей, одно место вещи, материал как общий словарь для света, звука и физики, анимационное состояние в симуляции. Решения боя и ragdoll от 2026-10-31 11:28 взяты как данность.

## 1. Опись мусора

Ядро в порядке: sim/, ai/, world/, io/ не включают render, бой SoA и детерминирован, арены без malloc в цикле, сохранение бит в бит, описания в data/defs с parent и модами. Мусор сидит на стыках: один и тот же человек, вещь и материал живут в нескольких местах, а game/ (35 файлов) смешивает симуляцию, вид и контент. Цена: М — до дня, С — 1–3 дня, Б — неделя и больше.

## 2. Слои и правило зависимостей

Шесть слоёв, каждый включает только строки выше себя. Шаг мира пишет sim, кадр только читает снимок (прошлый и текущий шаг, как сейчас last/body). Проверка — скрипт в CI, который ищет запрещённые #include.

| Слой | Папки | Что там | Может включать |
| --- | --- | --- | --- |
| 0 ядро | core/ | арены, RNG, математика, сетка, jobs, ser, журнал | ничего |
| 1 описания | defs/ | разбор текста, таблицы Def с именами (сетки, звуки — строками) | core |
| 2 мир | sim/, ai/, world/, io/ | реестр людей, вещи, объекты, физика, бой, ИИ, карта, отряды, сохранения; анимационное состояние (действие и доля) | core, defs |
| 3 контент | content/ (из game/: town, ostov, showhall, testroom, flora, props-генераторы) | генераторы форм по имени, сценарии тестовых сцен | core, defs, мир |
| 4 вид | view/ (figures, anim-позы, \*\_view, hud, sfx, сбор света) | позы, список отрисовки, огни, звуки, интерфейс | всё выше + render, audio |
| 5 приложение | app/ (main.c, controls, bench) | цикл, меню, ключи запуска | всё |

render/, audio/, platform/ — боковые слои: знают только core и platform, мира не видят. Вид держит таблицы «имя сетки → GpuMesh», «имя звука → SFX» и номера материалов GPU, построенные при старте по описаниям.

## 3. Целевая архитектура по подсистемам

Общее правило для всех: описание (Def) неизменно после загрузки, экземпляр хранит номер описания и только своё изменчивое состояние, сохранение пишет имена описаний (как сейчас DefMap). У каждого вида данных ровно один владелец, остальные держат номер (с поколением), а не копию.

### 3.1 Данные и описания

- Владелец: defs/. Пишет только загрузка при старте, читают все.
- Диск: нынешний формат data/defs/\*.txt (блок, «ключ значение», parent, mods/ правит поля). Новые виды: material, item (с компонентами), object, prefab, body, actionset, light; позже race, faction, place.
- Компоненты внутри записи вложенными блоками (`weapon { … }`, `armor { … }`, `light { … }`, `phys { … }`), как ThingComps у RimWorld. В памяти — плотные таблицы по виду компонента и у записи номера строк (u16, 0xFFFF — нет).
- Имена сеток, звуков и генераторов хранятся строками; вид и звук разрешают их сами (убирает №9). Список имён, нужных коду, проверяется при загрузке, как сейчас.
- Инструменты (tools/) собираются с core+defs без рендера: проверка мода, отчёт по балансу.

### 3.2 Вещи

- Описание: одна запись `item` с общими полями (имя, размер в клетках, вес, стопка, материал по умолчанию, вид на теле и на земле, hides) и компонентами weapon / armor / wear / container / light / phys. GEAR\_\* и g\_gear\_file уходят в описания (`look jacket` — имя сетки).
- Экземпляр `ItemStack`, 8 байт: def u16, материал u8, качество u8, число u8, износ u8, зерно u16 (оттенок, царапины). Уникальная вещь с историей — номер в пуле `Unique`.
- Место вещи — одно поле состояния: ЗЕМЛЯ (пул Ground + тело phys в зоне), РУКА, ТЕЛО (слот), СУМКА (сетка 9×6 как сейчас), СТОЙКА/ЯЩИК (объект с container). Переходы только через `item_move(from, to)` в sim/items.c: он же создаёт и гасит физическое тело и пишет событие в журнал. CombatWorld.gitem и Squad.pick становятся номерами вещи, а не своей логикой.
- Дальний LOD: отряд везёт товары числом (def → штук), без экземпляров; при приближении снаряжение тел собирается из зерна и выучки, как sheet\_random.

### 3.3 Объекты, экземпляры, заготовки

- `object`: форма (генератор по имени или .mesh), слоты материалов, phys (или статика), light, container, точки действия (сесть, стоять на посту, взять), режим расстановки осесть/висеть/намертво (уже есть в phys).
- Экземпляр: SoA по чанкам 256 м (def, положение, поворот, зерно, флаги состояния), \~32 байта. Владелец world/. Сохраняются только отличия от заготовки (сдвинуто, сломано, вынесено).
- `prefab`: список (object|prefab, матрица, замена материала, случайный выбор из набора), вложенный. Локация = заготовка + зерно. Скудель, Остов, Мерильня, зал переезжают сюда из C.
- Вид строит из экземпляров чанка статические пакеты на GPU и список огней; World больше не держит GpuMesh (№7). Дальний LOD: силуэт чанка одной сеткой, мегаструктуры — отдельный слой всегда.

### 3.4 Скелет, клипы и наборы действий

- `body`: скелет из .skel + роли костей (таз, позвоночник, голова, плечо/предплечье/кисть, бедро/голень/стопа), точки крепления (хват, ножны, спина), хит-капсулы и части ragdoll по ролям, метрики (рост, длина руки) вместо чисел под 1.8 м. Один человеческий скелет на все гуманоидные расы, раса меняет масштаб и сетку.
- Клипы: двоичный .anim (ключи по ролям костей, метки событий «удар», «стопа на земле», «рука на рукояти»). Источник — нынешние процедурные ключи anim.c, запечённые офлайн в tools/animbake; в игре остаются только слои на лету: фаза шага, IK рук и стоп, взгляд, дыхание.
- `actionset` (как ActionSets Bannerlord, с parent): имя действия → клип, длительность, смешивание, события. Наборы: human\_base → human\_onehand, human\_twohand, human\_polearm, human\_unarmed. Хваты по классу оружия — тоже тут.
- Анимационное состояние человека (действие, доля, прежнее действие и доля смешивания, как лежит) живёт в симуляции и тикает с шагом мира. Тайминги боя берутся из того же actionset. Вид только сглаживает и считает позу. FightAnim исчезает как источник решений (№3).
- Поза — чистая функция (состояние → матрицы), поэтому симуляция может её посчитать сама в момент перехода в ragdoll. LOD: рядом каждый кадр, дальше реже и без IK, далеко — точка отряда.
- Правила пользователя остаются: скорости реалистичны относительно друг друга, подъём не зависит от навыков.

### 3.5 Ragdoll и физика

- Владелец тел: sim/phys.c (свой XPBD, один поток, порядок по номеру, зона 150 м с гистерезисом 20 м, сон и застывание). Суставы шар/петля и группы тел — коммит 90c9430, берём как есть.
- Ragdoll = группа из 11 капсул, части и пределы суставов из `body` (по ролям костей). У человека в реестре режим тела: АНИМАЦИЯ / RAGDOLL / ЗАПЕЧЁННАЯ ПОЗА, и номер группы phys.
- Переход (смерть, сильное ошеломление): событие боя → поза из анимационного состояния симуляции → тела с начальной скоростью от удара. Без вступительного клипа (решение пользователя). При сильном ошеломлении оружие идёт через item\_move в ЗЕМЛЮ с скоростью кисти.
- Подъём: по ориентации таза выбирается «на спине / ничком / на боку», за 0.2–0.3 с поза сводится к первому кадру клипа подъёма.
- Уснувший ragdoll запекает позу в человека и освобождает 11 тел. Вне зоны — без ragdoll: поза лежания из клипа + settle\_limbs + склон (как сейчас, только дальний LOD).
- Толкание: стоящий — одна капсула (расталкивание боя), лежащий — капсулы ragdoll. Перенос — мягкая пружина к точке крепления несущего.
- Бюджет: 48 ragdoll в движении, 256 вещей, ≤ 2 мс на шаг. Позже — параллельно по независимым островам (детерминизм сохраняется).

### 3.6 Бой

- Решено пользователем 2026-10-31 и не меняется: попадание, урон и броня статистикой как в Kenshi; блок как в Kenshi, но клинки встречаются в заготовленных стойках; два ошеломления (лёгкое анимацией, сильное ragdoll с выбросом оружия); толкание капсулами; повтор бит в бит.
- Один CombatWorld на весь ближний мир, арена — место с правилами (fence\_r, mercy). Слот боя ссылается на человека в реестре; позиция и здоровье хранятся один раз (в реестре), горячие столбцы боя (таймеры, цель, удар) — плотно по слотам.
- Длительности — из actionset, балансовые числа (№8, №10) — в data/defs/combat.txt. Звук и искры попадания — по паре материалов (оружие × броня или клинок).
- LOD: подробно до 64 бойцов в зависимости от ситуации бойца (не камеры), дальше тот же бой реже, вдали — формула отрядов (bands.c). Тактический слой (командир, места, роли) пишет намерения, бой их исполняет.

### 3.7 Материалы и свет

- `material`: модель шейдера (одно из нынешних MAT\_*), цвета, шероховатость, металл, свечение, ржавчина/износ, звук удара и шага, трение и отскок, множители для вещей (как stuff в RimWorld). Заменяет PAL\_*, WeaponPart.color, ArmorDef.metal, voice, PhysDesc.friction (№5).
- На GPU — таблица материалов (UBO/SSBO), вершина несёт номер материала (u8 сейчас → индекс в таблице). Текстур не добавляем: рисунок даёт модель шейдера по сетке TEXEL.
- Источники света — компонент `light` у объекта и вещи (цвет, радиус, мерцание, тень да/нет, горит ли ночью). Симуляция держит только «горит/не горит», вид собирает PointLight из видимых чанков и людей с зажжённым факелом (№8).
- Конвейер света (этапы 1–5, наборы ПРЕЖНИЙ/БЫСТРЫЙ/РЕАЛИСТИЧНЫЙ) не трогаем: он лишь получает честные шероховатость и металл. Зонды и тени огней читают список огней из вида, как сейчас.

### 3.8 Люди: один реестр, ИИ и мир

- `Persons` (sim/persons.c) — единственная таблица людей с телами и заметных личностей. SoA, номер с поколением (u32: 20 бит место + 12 поколение), предел 2048 тел рядом. Столбцы группами: кто (имя, тело/раса, фракция, отряд, роль), тело (позиция, курс, скорость, прошлый шаг), лист (навыки, части тела, кровь), снаряжение, разум (потребности, память, текущая задача), анимационное состояние, режим тела и номер ragdoll, зерно внешности. Внешность (матрицы, список сеток) — кэш вида, в сохранение не идёт.
- Всё остальное становится списками номеров: Squad (уже так), слоты боя, ростер арены (люди с ролью «боец арены»), NearBands (чей человек). Команды боя отдельно от фракций (как в плане v5).
- LOD человека: ПОДРОБНО (в бою или рядом: каждый шаг) → ЛЕГКО (рядом, спокоен: ходьба и решения реже, как TickerType Rare у RimWorld) → ЧИСЛОМ (в отряде вдали: строка в Bands, заметные личности держат свою строку без тела). Проявление и растворение — одна пара функций, числа отряда сходятся бит в бит.
- ИИ (решено в v4): фракция HTN-лайт + utility → отряд HTN-лайт + utility → тактический слой боя → человек utility. ИИ читает реестр и пишет только намерения (куда, кого, действие) — исполнение делает мир. Гомеостат читает сводки фракций и мест.
- Шаг мира (jobs): ИИ и движение — параллельно по людям/отрядам (читают прошлый шаг, пишут своё); бой — по независимым схваткам; физика — одним потоком; события → журнал. Сохранение — столбцы реестра, как people\_ser сейчас.

### 3.9 Кадр

- Вид строит FrameView из реестра, чанков объектов, вещей на земле и огней. Один цикл поз по реестру (вместо трёх источников в figures\_draw), ключ сортировки явный, не адрес GpuMesh.
- Это же даёт потоку симуляции из шага 4 чёткую границу: кадр читает только снимок.

## 4. Образцы: что берём и что нет

Каждая часть раздела 3 опирается на решение, которое уже прошло проверку масштабом в реальной игре. Сведения об устройстве игр — из их файлов модификаций и вики моддеров, по памяти, без ссылок.
