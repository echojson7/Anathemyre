Подробности — в `docs/` по темам.

## Правила для всех шагов
- Каждый шаг: план → «да» → PR в stage0/test-room → «да» на влитие. Пункт закрыт, когда он влит и проверен у пользователя.
- Шаги одного потока идут строго по очереди, потоки не пересекаются по файлам. Граница файлов записана в промпте шага. Общие файлы (таблица видов в defs.c, Makefile, docs/README.md, bench.txt) правятся только дописыванием строк. Если двум потокам нужен один файл, второй не правит его, а спрашивает пользователя.
- SAVE_VERSION поднимает тот PR, который вливается, сразу после подмешивания свежей test-room. Перед PR подмешать test-room, CI зелёный, включая бит в бит мира, сохранений и бенчей. Открыто не больше трёх PR.
- Общие проверки: релиз, отладка (ASan/UBSan), Windows без предупреждений; бит в бит, где шаг не должен менять картинку или мир; столбец в ЗАМЕР ПО ЭТАПАМ для нового прохода; документация в docs/.
- Что нужно следующему шагу, закладывается в предыдущем, а не латается потом.
- Свет — у пользователя, его шейдеры и пункты СВЕТ никто не правит.

Клипы падения и смерти играются через мышцы ragdoll (решение пользователя 31.10, 17:01). Отрубленные куски — отдельный ragdoll, подбираются как вещь (в бюджете 48). Пункт 0 — перекос боя по номеру слота.
- Затем 3.2 сильное ошеломление (ragdoll, оружие через item_move на землю, подъём из позы).
- Поток 1 после 3.2: 3.3 обычное ошеломление как действие → 3.4 блок по направлению удара, звон и искры по паре материалов → 3.5 толкание капсулами.

- Готово, когда: до 48 ragdoll не дороже 2 мс на шаг, повтор боя бит в бит.

## Шаг 4. FPS
- 4а замер ЭТАПЫ / GPU / CPU своими силами (без замеров пользователя), в нём же разбор CPU-отправки кадра на Vulkan. Идёт параллельно с шагом 3.
- 4б GPU людей и явный ключ корзин рендера вместо адреса GpuMesh. Параллельно с шагом 3, свет не входит.
- 4в CPU: поток симуляции читает снимок реестра, позы одним пакетом job. После шага 3 целиком. Проверка боем 256–512 человек (битв на 1000 не будет).
