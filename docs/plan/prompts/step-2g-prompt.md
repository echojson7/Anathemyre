# Шаг 2г мастер-плана: скелет, клипы, наборы действий (промпт для рабочего треда)

Ты ведёшь шаг 2г, поток 3 этапа В (после 2е, PR #113). Цель — тело, клипы и действия описаны данными, а состояние анимации бойца становится фактом симуляции. На этом стоит весь шаг 3 (ragdoll и бой).

## Решения пользователя, не переспрашивать
- Клипы запекаются в .anim. Генераторы ключей из anim.c уходят, процедурные слои (походка от скорости, IK рук, наклоны) остаются кодом и читают ключи из файлов. Тогда клипы из Blender или захвата движений потом встанут на то же место.
- Состояние анимации бойца переезжает из вида в симуляцию. Эталоны боя один раз сдвинутся, это нужно объяснить.
- Клипы падения и смерти остаются. Ragdoll появится в 3.1, и там решат, как их совместить. Сейчас ничего из них не вырезать.
- Длительности реалистичны относительно друг друга и к навыкам не привязаны (правило 2026-10-30).
- Новые клипы в этом шаге не делать.

## Три PR по очереди
### PR 1. Описание body
- Новый вид `body` в data/defs: файл скелета (.skel), роли костей (таз, позвоночник, голова, плечо, предплечье, кисть, бедро, голень, стопа), точки крепления (хват, второй хват, ножны, спина, факел), хит-капсулы (сейчас g_body_hit_def), части ragdoll (11 капсул по ролям) с пределами суставов (конус, кручение, петля). Пределы пока только описаны, пользоваться ими будет 3.1, где их ждёт коммит 90c9430.
- Метрики от роста тела вместо метров под 1.8 м в коде. Это как Monster у Bannerlord и шаблоны тела у Dwarf Fortress.
- Точка хвата на самом оружии остаётся в описании вещи (это 2в), на теле — только точки крепления.
- Бит в бит: позы, бой, кадры.
### PR 2. Клипы в .anim
- tools/animbake — офлайн-инструмент, собирается с core и defs без рендера. Запекает 43 таблицы ключей из anim.c в data/anims/*.anim, это свой бинарный формат с версией, быстрый для загрузки. Игра читает файлы при старте в арену, без malloc в цикле.
- anim.c больше не держит таблиц: процедурные слои берут ключи из загруженных клипов.
- Проверка: хеш матриц поз всех клипов в 16 точках по времени до и после совпадает бит в бит. Плюс кадры, бой и витрина Мерильни (debug/).
### PR 3. Наборы действий и состояние анимации в симуляции
- Вид `actionset` с parent, как ActionSets у Bannerlord: основа «человек» → наборы по семействам оружия. Действие = клип по имени + длительность + скорость + метки (касание, удар, звук).
- Длительности, которые 2е оставил в коде (KNOCKED_S, GETUP_*, PICKUP_S, пошатывание, лёжа, возврат, проводка, удержание блока и уворота), переезжают в действия.
- Текущее действие, время старта, доля, лёжа ли и как (prone/side), куда упал — SoA-столбцы в мире боя, они идут в сохранение (SAVE_VERSION +1). Вид только сглаживает показ. FightAnim остаётся кэшем вида, без решений о мире.
- Сдвиг эталонов боя показать один раз: суммы до и после, почему разошлись. После этого повтор бит в бит снова обязателен, проверка save_check.sh.
