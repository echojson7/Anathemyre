# Шаг 2б мастер-плана: объекты, заготовки, чанки (промпт для рабочего треда)

Ты ведёшь шаг 2б, поток 1 этапа В. Цель — постройки и детали локаций перестают быть кодом и становятся данными: описание object, заготовка prefab, экземпляры по чанкам.

## Что сделать (2–3 PR по очереди)
1. **Виды object и prefab в data/defs.** object: форма (генератор из content/ по имени или .mesh), слоты материалов (по имени материала), статика для физики (коробки/капсулы в описании), режим расстановки осесть/висеть/намертво (уже есть в phys), компонент light (цвет, радиус, мерцание, тень да/нет, горит ли ночью), точки действия — только как поле на будущее, без логики. prefab: список (object|prefab, положение, поворот, замена материала, случайный выбор из набора по зерну), вложенный. Как ThingDef+comps у RimWorld и pack-in у Bethesda.
2. **Экземпляры в world/.** SoA по чанкам 256 м (def, положение, поворот, зерно, флаги), около 32 байт, пул при старте, без malloc в цикле. Локация = заготовка + зерно. Отличия от заготовок НЕ сохраняются (решение пользователя: локации тестовые), сохранение их не пишет. Стена, дверь, перекрытие — отдельные экземпляры, не склеенная сетка (под будущее строительство).
3. **Перевод локаций.** Первой Скудель (content/town_build.c), затем Остов и зал. Нынешние сцены тестовые: перенос делается ради формата, точная копия не обязательна, но держаться близко и показать кадры «было/стало».
4. **Вид строит из экземпляров чанка статические пакеты** (view/scene.c), без нового GpuMesh в мире.
5. **Свет как компонент.** Одна функция сбора огней в view/ (новый файл) из видимых экземпляров с light вместо hall/ring/showhall/testroom *_lights и склейки в main.c. Факел в руке (torch_light в figures.c) не трогать: он станет компонентом вещи в 2в и подключится к твоей функции одним вызовом.
6. **Статика для физики** из описания object: лом и вещи больше не падают сквозь постройки (этап 3.7 отменён, это он).
