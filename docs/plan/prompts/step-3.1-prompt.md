# Шаг 3.1 мастер-плана: ragdoll убитых (промпт для рабочего треда)

Ты ведёшь шаг 3.1, первый шаг ragdoll и боя. Шаг 2 закрыт целиком (последний — #123: PEOPLE_MAX 512, NEAR_BODIES 256, SAVE_VERSION 12, --bench battle512 с базой в docs/performance.md): тело описано в bodies.txt (11 частей ragdoll с пределами), клипы лежат в .anim, действия — в actionsets.txt, состояние анимации хранится в мире боя (столбцы act*), есть один реестр людей Persons (2д: раны, кровь, навыки, act* — столбцы Persons, бой поля связан через combat_bind_body). Арена по решению пользователя осталась со своим боем в debug/: ragdoll должен работать и там, через тот же код.

## Решения пользователя, не переспрашивать
- Попадание, урон и броня — статистика как в Kenshi. Ragdoll на исход боя не влияет.
- **Клипы падения и смерти играются через мышцы ragdoll (решение 31.10, 17:01).** Тело с удара сразу физическое, вступительного клипа без физики нет. Мягкие цели суставов (motor в XPBD) ведут тело по клипу падения или смерти, их сила спадает до нуля к концу клипа. Клип виден, но тело чувствует землю, стены и других.
- Отрубленные куски, как в Kenshi, лежат отдельным ragdoll (части из body), их можно подобрать как вещь (item с компонентом ragdoll, через item_move). Они входят в бюджет 48.
- Бюджет: 48 ragdoll в движении, не больше 2 мс на шаг. Повтор бит в бит обязателен (-ffp-contract=off, свои sin/cos, порядок по номеру).
- Зона 150 м с гистерезисом 20 м, сон, застывание вне зоны — как в docs/physics.md. Вне зоны ragdoll нет: поза лежания из клипа + settle_limbs + склон (дальний LOD).
- Замеров у пользователя не просить.

## Что сделать
0. **Отдельным маленьким PR до ragdoll:** перекос боя по номеру слота. После 2д (#123) в --bench battle512 сторона с меньшими номерами проигрывает 256 против 29, то же видно в field 400. Похоже на порядок обхода: кто раньше в цикле, тот раньше бьёт или раньше получает урон за тот же шаг. Найди причину и сделай исход независимым от порядка слотов: двухфазный шаг (все решают по прошлому состоянию, затем применяется), детерминированный порядок без привилегии по номеру. Проверка: зеркальный бой (стороны поменять местами) даёт зеркальный счёт в пределах разброса зерна. Бенчи один раз сдвинутся, объяснить. Это база для всех замеров шага 3.
1. **Первым коммитом** перенести наработку суставов XPBD — коммит 90c9430 с ветки claude/project-thread-7flpux (шар с конусом и кручением, петля, группы тел) — на свежую test-room. Конфликты решать в пользу нынешней архитектуры.
2. Ragdoll = группа из 11 капсул, части и пределы из g_body.rag. Знак сгиба и оси суставов выставить и проверить (в описании они пока черновые).
3. Режим тела в реестре Persons: АНИМАЦИЯ / RAGDOLL / ЗАПЕЧЁННАЯ ПОЗА и номер группы phys. Переход по событию боя (смерть): поза старта — из состояния анимации симуляции (act*), начальная скорость — от удара.
4. Мышцы: цель каждого сустава — поза клипа действия в момент t, сила спадает по кривой из описания действия (actionsets.txt: новое поле, например muscle_fade). Цели считаются в симуляции, вид только рисует.
5. Уснувший ragdoll запекает позу в человека и освобождает 11 тел.
6. Отрубленный кусок: отдельная маленькая группа из частей body, вещь в мире, поднимается и носится.
7. Вид рисует тело из поз ragdoll. В Мерильне (debug/) площадки смерти показывают ragdoll с мышцами по кругу.
8. Сохранение: режим тела и запечённая поза. Летящий ragdoll при сохранении досчитывается до сна (как решено для физики: «досчитывать»). SAVE_VERSION +1.
