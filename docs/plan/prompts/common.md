# Общее для всех шагов (агент в Cursor)

Этот файл подставляется в каждый промпт шага. Где в старых промптах написано «мастер-тред „Вести план работ по шагам“», это теперь `docs/plan/README.md`, ссылки на claude.ai-документы — `docs/plan/plan.md` и `docs/plan/architecture.md`, память проекта — `docs/plan/memory/`.

## Прочитать до начала
- `CLAUDE.md` — правила, стек, сеттинг. `docs/plan/README.md` — где остановились.
- `docs/plan/architecture.md`, разделы 1–3, 8 и 9 (раздел 9 «Решения пользователя» главнее остального).
- `docs/code.md` (слои, `tools/layers.sh`), `docs/debug.md` (`--bench`, сценарии в `data/debug/bench.txt`), `docs/performance.md`.
- Файлы памяти, которые назвал промпт шага.

## Устройство, которое уже есть (после шага 2, #123)
- Слои: core → defs → sim/ai/world/io → content → view → debug → app; render/audio/platform боковые. `tools/layers.sh` в CI ловит запрещённый `#include`. `make NODEBUG=1` собирает игру без `src/debug/` — должна собираться и после тебя.
- Отладка меняет мир только через `World.hook` (очередь команд раз за шаг). Арена у стартового зала остаётся как есть, со своими Ground/Phys, в сохранение не идёт (решение пользователя 31.10, 17:21), но новые механики боя должны работать и в ней через тот же код.
- Люди: реестр `Persons` (sim/persons.h), 512 мест с поколениями, столбцы места, ран, навыков, act*. NEAR_BODIES 256. Числа боя — `data/defs/combat.txt` (`g_tune`), тело — `data/defs/bodies.txt` (`g_body`, 11 частей ragdoll), действия — `data/defs/actionsets.txt`, клипы — `data/anims/*.anim` (исходник `tools/animbake/keys.c`, `make anims`, эталон `tools/animbake/poses.hash`). Вещи — запись `item` с компонентами, перемещение только через `item_move`. Материал даёт звук удара (`impact`). Одно трение и один отскок на весь мир.
- SAVE_VERSION на момент передачи — 12.

## Порядок работы
1. Короткий план пользователю (что, какие файлы, какие решения нужны от него) → ждать «да» → код.
2. Перед PR подмешать свежую `stage0/test-room`, собрать, дождаться зелёного CI.
3. PR только в `stage0/test-room`. Влитие — по «да» пользователя.
4. После влития: отметить шаг в `docs/plan/README.md` (раздел «Где остановились»), записать в `docs/plan/memory/` то, что нужно следующим шагам (имена, ключи, подвохи), и предложить пользователю следующий промпт.

## Правила
- По-русски. Идентификаторы по-английски, комментарии по-русски, кратко.
- Замеров и скриншотов у пользователя не просить: мерить самим `--bench`, кадры `make shot` (xvfb + lavapipe, пикселизация выключена, время суток одно и остановлено). Без лишних прогонов: CI проверяет сборки.
- Пользователь запускает только `cd ~/anathemyre-dev && git pull && ./tools/run.sh --novsync`. Других команд ему не давать.
- Свет и шейдеры света (группа СВЕТ) пользователь делает сам: не трогать и не подстраиваться.
- Код не беречь: что лучше переписать — переписать, но механик сверх задачи не добавлять. Нет malloc/free в игровом цикле, SoA, детерминизм бит в бит (-ffp-contract=off, свои sin/cos, порядок по номеру).
- Каждое изменение механики обновляет свой файл в `docs/` в том же коммите.
- Параллельные шаги: граница файлов из промпта обязательна. Общие файлы (таблица видов в defs.c, Makefile, docs/README.md, bench.txt) только дописывать строками. SAVE_VERSION поднимает тот, кто вливается, после подмешивания свежей test-room. Не больше 3 открытых PR. Нужен чужой файл — не править, спросить пользователя.
- Проверка каждого PR: релиз, отладка (ASan/UBSan), Windows (mingw) без предупреждений; layers.sh чистый; сумма мира, `save_check.sh`, `defs_check.sh`, бой и бенчи бит в бит, если в шаге не сказано иное. Любой сдвиг объяснить один раз.
