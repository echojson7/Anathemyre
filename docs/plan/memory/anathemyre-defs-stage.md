Этап 6 плана фундамента (описания вещей в текстовых файлах, формат для модов). PR #94 влит в stage0/test-room 2026-10-30 15:52 по «да» пользователя. Код: src/defs/{deftext,defs}.c, data/defs/*.txt, docs/content.md, проверка tools/defs_check.sh (в CI под ASan).

Решения:
- data/defs/*.txt: блок `weapon ressora`, поля «ключ значение», # — комментарий; ключи английские, тексты русские. Виды: weapon, armor, goods, attack, quality.
- Одна запись на вещь: бой, слот, размер, вид (`look jacket`), `hides pants/hair`, голос, форма оружия (paint мат r g b, rod, box). Перечисления A_*/G_*/W_* уходят, список GEAR_* остаётся манифестом конвертера.
- `parent <id>` копирует запись (как RimWorld). Моды: mods/<имя>/*.txt после встроенных; запись с тем же именем правит только указанные поля. Ошибка: «ОПИСАНИЯ: файл:строка» в журнале, игра не стартует.
- Сохранение пишет имена описаний (DefMap), при загрузке пересчёт номеров; имени нет — отказ, мир не тронут (Ser.refused). Поднять SAVE_VERSION (после #89 основа могла уже стать 2).
- В этап же: FightAnim не в сохранении; время суток из номера шага (world.c, без накопления f32).
- Наборы арены, свой отряд, тестовые сцены ищут вещи по имени (def_weapon/def_armor/def_goods); список нужных коду имён проверяется при загрузке. Переедут с фракциями.
- Числа — свой разбор (мантисса/10^n в double → float), не strtof.

Договорённость с тредом архитектуры кода: общий разборщик в src/defs/ (deftext.{h,c} зависит только от core), их клипы и наборы действий в том же формате. defs/ может включать sim, sim не включает defs/. Пересечения при слиянии: look.c (верх, скелеты), main.c (загрузка после find_data_dir), combat.c.

Сделано сверх плана: SAVE_VERSION 3, Ser.refused; FightAnim вне сохранения (fight_anim_settle после чтения); сутки — целое число шагов (DAY_TICKS). Тред «Проверить архитектуру и переиспользование» (материалы, object, prefab как в RimWorld/Bethesda) добавит свои виды записей в defs.c после мержа; поля материала в Item я отказался закладывать заранее.

Подвох: рендер сортирует по адресу GpuMesh — держать `GpuMesh weapon[WEAPON_CAP]` внутри CharMeshes.
