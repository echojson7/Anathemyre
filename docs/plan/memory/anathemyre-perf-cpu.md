PR #53 влит в stage0/test-room 2026-10-29 по «да» пользователя. В нём:
- pose_cull: позы вне кадра пропускаются, тень учитывается;
- корзины вместо qsort в gather;
- кеш масштабов костей;
- swap после логики: пункт «SWAP ПОСЛЕ ЛОГИКИ», без vsync;
- grid_count для морали в бою.

Картинка бит в бит, суммы боёв те же. Строка ЗАМЕР теперь: «логика X (сим, позы: N шт.), отправка Y (сбор Z), swap».

Узкие места и план — в docs/performance.md:
- поток симуляции с пакетом кадра;
- один SoA-список людей;
- постоянный буфер костей 3×4;
- MultiDrawIndirect;
- тик боя в потоке.

Этап 1 (PR #60, влит 2026-10-29): таблица People (src/game/people.c, номер = ID = слот поля, порядок таблицы = порядок rng), позы в jobs_for (figures.c), main.c разложен (world, figures, camera, controls, bench, humans_row), зоны core/prof.c в строке ЗАМЕР. Контейнер: логика 0.228 → 0.147 мс, позы 0.163 (1 поток) → 0.078 (4). 8 из 9 кадров бит в бит, кадр --attack иной из-за порядка слотов.
Подвох: рендер сортирует корзины по адресу GpuMesh, от этого зависит картинка (равная глубина кожи и одежды) и цена GPU. Прежний порядок держится выделением CharMeshes.gear в perm раньше World. Нужен явный ключ сортировки.

Делёж с тредом шейдеров: CPU-сторона (логика, позы, сбор и отправка в render.c, поток симуляции) у треда «Разобрать архитектуру кода ради FPS», а шейдеры и GPU-проходы — у FPS-треда.

**Why:** чтобы следующий тред знал, что уже сделано и что ждём.
Замер пользователя 2026-10-29 (RTX, 3440x1440): CPU 0.18–0.23 мс, swap после логики даёт +10–20 к/с (310 → 320–330), остаётся вкл. Лишние ~0.65 мс swap — показ кадра в Windows, им занимается FPS-тред (DXGI flip).
**How to apply:** CPU сейчас не узкое место; следующий этап (поток симуляции) начинать только по слову пользователя. См. [[anathemyre-fps]].
