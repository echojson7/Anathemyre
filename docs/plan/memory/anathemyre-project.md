Anathemyre: open-world sandbox (мир как Kenshi, визуал как Peripeteia), чистый C11/C17 + Makefile, без сторонних библиотек в рантайме. Репозиторий: github.com/echojson7/Anathemyre (сохранён в проект; рабочая ветка запуска stage0/test-room, с 2026-10-29 готовое вливать в неё, не в main). Полные правила в CLAUDE.md в корне репо (PR #1, 2026-10-28; копия в /mnt/project-files/anathemyre/CLAUDE.md).

Ответы пользователя 2026-10-28:
- Платформы: сначала Linux + Windows, позже macOS.
- API: хочет OpenGL сейчас, Vulkan потом → нужен тонкий слой бэкенда рендера.
- Железо: ориентир — системки Peripeteia (CPU после 2015, 6–8 ГБ ОЗУ, дискретная GPU уровня SM5/DX11, рекоменд. GTX 970).
- Масштаб: «как в Kenshi»; остальные решения пользователь отдал мне (цели: до 50k NPC абстрактно, ~500 в сцене).
- OpenGL 4.5 core подтверждён; офлайн-конвертеру разрешены сторонние библиотеки.
- Хотел сразу тестовую комнату с персонажем и стилем «на 85% как Peripeteia/Kenshi», без перфекционизма.
- Модели персонажей: Claude делает процедурно в коде; для качественных — CC0/художник/AI-генераторы.
- Есть второй мощный ПК для запуска; процесс: ./tools/run.sh <ветка> (pull+make+run), CI в GitHub Actions. 2026-10-29 18:35–18:59 задачи Actions падали за 3 с без машины и лога (лимит аккаунта, пользователь починил); если повторится — сказать ему и гонять шаги build.yml локально (mingw и libclang-rt-18-dev ставятся apt).

Статус 2026-10-28: этап 0 (тестовая комната) в PR #2, ветка stage0/test-room. Скриншоты кадров: make shot или --shot file.ppm под xvfb-run с LIBGL_ALWAYS_SOFTWARE=1.

**Why:** пользователь (lakinsbeast) требует, чтобы правила действовали в каждой сессии.
**How to apply:** отвечать по-русски; сначала план и ждать подтверждения, потом код; короткие этапы с собранным и проверенным результатом.

Машина пользователя для запуска: Windows + WSL2 (Ubuntu, Mesa 26), NVIDIA RTX 5070. В WSL нужен GALLIUM_DRIVER=d3d12 (run.sh ставит сам); этап 0 даёт ~420 к/с (2.4 мс) при 640x360.
Визуал (2026-10-29): пользователь отверг эффекты старого монитора (сканлайны, помехи, аберрация, дизеринг) — оставить только зерно. Общий стиль ему пока «не понравился», конкретика запрошена. Следующий этап одобрен: нативный порт Win32+WGL.
Отзыв 2026-10-29 по картинке: цвет слишком тусклый → реалистичнее; тумана больше; геометрия и формы сложнее; походка NPC должна быть правильной.
Подход (2026-10-29, слова пользователя): как в Kenshi — механики и логика продуманы до мелочей, а не плодятся. Значит: перед новой механикой — дизайн-документ на согласование, потом код.
Запрошено: арена (ринг) рядом с залом, где NPC дерутся мечами — дизайн боя на согласовании.
Нативная Windows-сборка на RTX 5070: 0.23 мс/кадр (640x360), GPU 0.2 мс.
Бой (2026-10-29, слова пользователя): «полностью как в Kenshi, в 2 раза сложнее и продуманнее»; закладывать массовые баталии, удары по нескольким целям сразу. Стандарт тела: основные персонажи и большинство — комплекция как у нынешних тестовых NPC (класс H), крупные расы отдельно позже (класс L, та же топология). Дизайн-док боя v2: https://claude.ai/artifact/UbQheLsG6o9LBwWgfGM1SV — код только после «да».
Решения по бою (2026-10-29): смерть на арене редкая (без добивания); отсечение конечностей есть, протезов пока нет; урон по своим всегда; выносливости нет; износа нет; схватки 4×4 каждый 5-й бой; отдельную клавишу камеры на ринг не делать (лишний код — пользователь против лишнего кода). Тон как в Kenshi или проще.
Управление своим персонажем (2026-10-29, выбор пользователя): как в Kenshi — ПКМ по земле, персонаж идёт туда; WASD остаётся у камеры, F следует за персонажем. Поиск пути отдельным этапом.
Этапы боя А1–А4 сделаны 2026-10-29: --arena-bench, --battle-bench A B [--threads N] [--battle-verify], арена в окне у зала (центр 14,0,34).
HUD (2026-10-29): PR #3 (ветка claude/project-thread-x8phe0, база stage0/test-room) — свой шрифт 5x7, отряд из 4, выбор/рамка, панель, окно осмотра (I) с инвентарём. Проверка ввода под Xvfb: самодельная утилита на libXtst (xdotool нет).
