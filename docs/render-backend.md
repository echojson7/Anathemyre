# Слой рендера (rb)

Состояние на 2026-10-30. Код: `src/render/rb.h` (API), `src/render/rb_gl.c` (OpenGL 4.5), шейдеры `data/shaders/rb.glsl`
и `frame.glsl`. Вызывают слой `render.c`, `terrain.c`, `ui.c`; напрямую к GL больше никто не обращается.

## Зачем
Рендер переходит на Vulkan вторым бэкендом, GL остаётся эталоном и запасным путём. Чтобы новый свет не писать
дважды, весь рендер говорит с видеокартой через один тонкий слой: буферы, текстуры, конвейеры, проходы, вызовы.
Под слоем сейчас GL, следом встанет `rb_vk.c` с тем же `rb.h`. Шейдеры общие (GLSL 450), различия GL и Vulkan
спрятаны в `rb.glsl`.

## Правила слоя
| Правило | Почему |
|---|---|
| Ручки `RbBuf`, `RbTex`, `RbPipe` — числа, 0 — нет | никаких указателей на объекты драйвера |
| Привязки (`rb_bind_*`) и константы вызова (`rb_push`) живут до перезаписи | как блоки текстур в GL; смена конвейера их не сбрасывает |
| Буфер `RB_BUF_DYNAMIC` пишется кольцом по `rb_frame_slot()` (3 кадра в полёте) | Vulkan читает буфер позже, чем CPU пишет следующий кадр |
| Барьеры между проходами ставит слой | он знает, что проход пишет и что читает; render.c о них не думает |
| Кадр в памяти как в GL: строка 0 внизу | Vulkan переворачивает только при показе, шейдеры не меняются |
| Состояние GL кешируется в `rb_gl.c` | лишние вызовы не доходят до драйвера |

## Константы
- **Frame** (`frame.glsl`, `GpuFrame` в render.c, 288 байт): всё, что одинаково во всех проходах кадра — матрицы,
  камера, солнце, небо, дымка, флаги этапов, размер пикселя. Пишется раз за кадр. У каждого портрета свой блок:
  своя камера и `u_unlit = 1`, остальное — копия кадра.
- **u_push** (128 байт, `uvec4 u_push[8]`): что меняется от вызова к вызову. Сцена и тени (`ScenePush`):
  `[0..3]` матрица прохода, `[4]` вид сетки, начало экземпляров, морфы, `[5]` прореживание, `[6]` `[7]` рельеф.
  Интерфейс: размер цели и время. В GL это массив uniform, в Vulkan — push constants.

## Конвейеры сеток
Набор на проход (тени, глубина, сцена, портрет) × раскладка (обычная сетка, общий буфер людей, рельеф без вершин)
× отсечение граней (без отсечения — только экземпляры листьев и травы). Сетке без весов костей слой подставляет
поток нулей: вес первой кости 0 — жёсткий скиннинг, как раньше без потока.

## Частота шейдинга (VRS)
Проход получает карту частоты полем `RbPass.rate`, барьер после её записи ставит слой. Конвейер с `frag_size`
читает размер блока как `RB_FRAG_SIZE` (в GL — `gl_FragmentSizeNV`). Подробно о картах — [pixels.md](pixels.md).

## Как добавить проход (для света)
1. Шейдер — список файлов в `RbPipeDesc`; если нужны константы кадра, первым идёт `frame.glsl`.
2. Текстуры и буферы — на свободных привязках 27–31; новое общее поле кадра — в конец `Frame` и `GpuFrame`.
3. Проход: `rb_pass_begin` с целями → `rb_bind_pipe` → привязки → `rb_draw` / `rb_dispatch` → `rb_pass_end`.
4. Метка времени — новый `PASS_*` в render.h и `mark` / `pass_mark` вокруг прохода: так он попадёт в ЗАМЕР ПО ЭТАПАМ.

## Проверка
Переход на слой не меняет ни одного пикселя: 24 кадра (этапы сцены 0–11, близко и далеко, ночь, долина, люди,
стенд, осмотр, без пиксельности, без VRS, без MultiDraw, AO в половине, шум хешем) совпали с прежней сборкой
байт в байт, кроме цифр счётчика к/с. Отладочная сборка с ASan и отладочным выводом GL — без ошибок.
