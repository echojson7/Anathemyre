# Пиксельность кадра

Состояние на 2026-10-29. Код: `data/shaders/pixel.glsl`, `data/shaders/scene.frag` (seam_line), `data/shaders/ao.glsl` (depth_normal) (level_at, pixel_q, pixel_src), `data/shaders/level.frag`,
`data/shaders/level_max.frag`, `data/shaders/src_map.frag`, `data/shaders/style.frag`, `src/render/render.c`
(PIXEL_K, PIXEL_P).

## Как устроено
- Кадр рисуется в полном разрешении окна, потом фильтр кадра берёт цвет каждого пикселя из «источника» —
  центра ячейки, в которую пиксель попал. Одно правило для всего кадра, без отдельной обработки объектов.
- Размер ячейки зависит от глубины точки: `k = PIXEL_K · s^PIXEL_P`, s — пикселей кадра на метр мира в точке.
  Поэтому при большем окне пиксели в тех же метрах чуть крупнее в пикселях кадра.
- Размеры квантуются: шаг 0.25 пикселя кадра до 2, выше шаг 0.5. Вдали не мельче 1.25, вблизи не крупнее 8.
- Два порога замедляют рост к камере, чтобы люди вблизи не становились крупнопиксельными:
  - `PIXEL_KNEE` 1.75 (ближе ~6 м при 1080p) — рост вдвое медленнее;
  - `PIXEL_KNEE2` 2.0 (ближе ~5 м) — самый близкий порог, рост ещё в 3.3 раза медленнее.
- Ячейка берёт цвет ближайшей к камере из четырёх точек, чтобы тонкие прутья не рвались в пунктир.
- Размер пикселя считается раз за кадр (level.frag), источник — тоже раз за кадр (src_map.frag);
  по той же карте строится частота шейдинга (VRS).
- Меню НАСТРОЙКИ: ПИКСЕЛЬНОСТЬ выключает всё (`RenderSettings.pixel`). Фильтр кадра пишет прямо в окно,
  отдельного прохода апскейла нет.
- Отвергнутые способы (вырезаны 2026-10-29 по решению пользователя, были пунктом меню ПИКСЕЛИ для сравнения):
  целые размеры 1-2-4-8 (быстрее: ячейки ложатся на блоки шейдинга, а вдали пикселизации нет совсем, но пользователю
  нужна пиксельность и вдали) и весь кадр в 1/2 или 1/3 окна.

## Тонкие детали на квадратах TEXEL
Материал считается в центре квадрата 1/10 м. Рисунок тоньше квадрата (швы плит пола 4×4 м, швы опалубки на стенах)
центр квадрата не задевает, и он пропадал при включённой пиксельности. Теперь швы рисует `seam_line` (scene.frag):
темнеет ровно тот квадрат, через который проходит линия шва, слабее во столько, во сколько квадрат шире шва.
Без квадратов (вдали или с выключенной пиксельностью) шов прежний, гладкий.
Новый тонкий рисунок на поверхностях рисовать так же: по сетке квадратов, иначе он исчезнет.

## Шейдинг блоками (VRS)
Где все пиксели блока 2×2 или 4×4 берут цвет из одной ячейки, сцена и атмосфера считаются раз на блок
(GL_NV_shading_rate_image, пункт меню «ШЕЙДИНГ БЛОКАМИ»). Найденные ошибки и что с ними сделано:
- Нормаль для затенения углов (AO) считалась через `dFdx/dFdy` глубины. При шейдинге блоками производная берётся
  через соседний блок, на 2–8 пикселей. У края предмета соседний блок лежит на другой поверхности, нормаль выходит
  ложной, и весь блок затеняется почти в чёрное: чёрные полосы вдоль краёв. Теперь нормаль строится по соседним
  пикселям глубины (`depth_normal`, ao.glsl), по каждой оси с той стороны, где глубина ближе. Без блоков кадр почти тот же.
- Объёмный свет (rays.frag) считается в половинном разрешении, а карта блоков задана в пикселях полного кадра:
  блоки ложились не на свои места. Теперь карта блоков выключена для всех целей половинного разрешения.

## Проверка
`--size 1920 1080 --tod 0.4 --day-stop --cam 14 32 -0.5 0.42 <дальность> --frames 30 --shot <файл>`:
пикселизация включена, время суток одно, сутки стоят. При дальности камеры 17 м кадр совпадает с прежним,
кроме счётчика кадров.
